# Checklist para análise de software ou produto educacional

Use evidências. Não marque um critério apenas pela impressão geral da interface.

| Critério | Pergunta orientadora | Evidência observada | Avaliação |
|---|---|---|---|
| Finalidade | O recurso contribui diretamente para o objetivo? | | |
| Conteúdo | O conteúdo é correto, adequado e atualizado para a tarefa? | | |
| Atividade cognitiva | O estudante precisa interpretar, decidir, produzir ou apenas clicar? | | |
| Feedback | O retorno ajuda a compreender erros e avançar? | | |
| Adequação à turma | Linguagem, complexidade e ritmo são apropriados? | | |
| Usabilidade | É possível compreender como começar, prosseguir e voltar? | | |
| Acessibilidade | Há barreiras de visão, audição, mobilidade, linguagem ou navegação? | | |
| Privacidade | Solicita dados necessários? Há controle sobre compartilhamento? | | |
| Viabilidade técnica | Funciona nos dispositivos e na conectividade disponíveis? | | |
| Autoria/portabilidade | É possível exportar, guardar ou reutilizar o trabalho? | | |

## Uso de IA na atividade

A IA pode apoiar a formulação de critérios ou perguntas de teste, mas não substitui a avaliação prática do produto. Toda conclusão deve ser sustentada por observação direta, teste, documentação oficial ou fonte verificável.

Se houver uso de IA, registre a ferramenta, a finalidade e o que foi efetivamente verificado. Funcionalidades inexistentes, referências inventadas ou conclusões não testadas comprometem os critérios de evidência, fundamentação e autoria.
